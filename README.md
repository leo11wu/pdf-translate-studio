# 纸间 · PDF 译制台

把一份 PDF 翻译为中文，尽量保留版式，并导出原文、译文 TXT。

**这是已经打包好的 Mac 软件。普通使用无需安装 Python、Node 或开发工具，也无需使用终端。首次需要设置自己的翻译 API，保存后即可日常使用。**

## 第一次使用

1. **解压并打开。** 双击 ZIP 解压，把“纸间.app”拖入“应用程序”，再双击打开。
2. **如遇首次打开提示。** 当前组内版本尚未经过 Apple 公证。若提示无法验证开发者，尝试打开后，到“系统设置 → 隐私与安全性 → 仍要打开”，为这份确认来源的 App 允许一次。可参照 [Apple 的打开说明](https://support.apple.com/zh-cn/102445)。
3. **等待自动准备。** 首次联网自动下载约 350 MB 的 PDF 版式资源和字体，无需手动安装。完成后显示“模型与字体已就绪”；以后会复用已下载的资源。
4. **设置翻译服务。** 点击“新建配置”，展开“API 地址与钥匙串设置”，填写下表信息，选择模型；给配置起名，勾选“安全记住 API 密钥”，点击“保存配置”。以后可在“已保存的 API 配置”中直接切换，地址、密钥、模型和速度设置一起恢复。

| 界面中的项目 | 填什么 |
| --- | --- |
| API 基础地址 | 翻译服务提供的地址；可以直接复制组内维护者给你的地址。 |
| API 密钥 | 你自己的服务密钥，可向供应商获取。每位组员使用自己的密钥。 |
| 翻译模型 | 从自动获取的列表里，选择组内推荐的文本翻译模型。 |

如果你不了解 API，第一次可请组内维护者协助填好地址、密钥和模型。这些设置都在 App 界面里完成，不需要改代码或配置文件。翻译会使用你个人服务的 API 额度，并需要联网；App 不附带翻译额度。

## 平时怎么用

1. 打开“纸间”，拖入一份 PDF，点击“开始译制”。
2. 等待完成；默认同时得到中文 PDF、原文 TXT 和译文 TXT。
3. 在“下载 → 纸间译文”中查看结果。每次任务有独立文件夹，也可从 App 的“输出与历史”重新打开。保存位置可在 App 中更改。

只需要原文文字时，可点击“仅提取原文 TXT（不调用 API）”，无需设置翻译服务。

复杂表格、扫描件、页眉和特殊版式建议先试译一两页。TXT 保留分页和换行，用于研究前请核对文字与读取顺序。

## Mac App：组内轻量分发

- Apple 芯片（arm64），macOS 14 或以上；原生 AppKit / WebKit 窗口，生产界面静态打包，不携带 Node、Electron、Cloudflare 服务或开发依赖。
- 自带裁剪后的 Python / PDF 引擎，组员无需安装开发工具。首次使用会下载约 336 MiB（约 350 MB） 的模型、字体和字符映射，使用固定哈希校验、原子写入，并复用已完成文件。
- 每人配置自己的 OpenAI-compatible API 地址；支持自定义基础路径，自动读取 `/models` 并选择模型，也可手动输入。不支持原生 Anthropic/Gemini 等不同请求协议，需使用兼容端点。
- 在界面勾选“安全记住 API 密钥”并保存后，密钥由原生窗口写入 macOS 登录钥匙串；每套密钥按独立配置 ID 保存；普通偏好设置只含名称、地址、模型和速度设置。未记住时仅在 App 会话内保留。更改地址不会沿用原地址的密钥。
- 桌面版完全忽略开发目录里的 `api_config.txt` 和开发者的 API 环境变量。分发采用源码白名单，不包含密钥文件、历史 PDF、任务目录或模型缓存。
- 每次启动使用随机回环端口和内存会话凭据；仅当前窗口可以访问接口、进度流和下载。默认自动保存到 `~/Downloads/纸间译文/`，可选择统一目录；每个任务独立文件夹，已有结果不覆盖。单文件另存仍使用 macOS 保存窗口。退出会清理本次启动的服务及翻译子进程，运行任务时先询问是否取消。
- App 数据位于 `~/Library/Application Support/PaperStudio/`。保留单文件翻译、取消、长文分段、纯译文和可选对照版；暂不增加批量或断点续传。默认自动从 4 个在途请求、每秒 2 次开始，每连续成功 8 次增加 2 个在途请求，最高 16 个；高级设置可手动调整上限与请求速率。
- 0.3 起支持持久历史、搜索、模型/接口/阶段耗时记录，重启后可下载和重新保存；桌面任务不再自动过期。0.2.0 已有的可读本地结果会导入历史，不推断旧任务的模型或耗时。
- 可同时导出原文和译文 UTF-8 TXT，也可仅提取原文 TXT，无需 API。TXT 保留页码和换行，普通双栏按栏读取，来自 PDF 文本层；不做 OCR 或研究语料清洗，复杂版式需核对。
- 完全相同的 PDF、接口、模型与翻译设置可复用已验证完成结果，使用文件哈希检查完整性，不调用模型；高级设置可关闭复用。旧的段落缓存继续跳过，避免历史污染。首次翻译仍受模型延迟、并发和本地排版影响。

### 0.4：翻译链路与 API 历史

修复 0.3 的首次资源路径问题：主服务、翻译子进程和 PDF 保存助手均在导入引擎前使用同一份 `Application Support/PaperStudio/engine-cache`。界面下载完成后不再依赖 `~/.cache/babeldoc` 的旧文件；升级后无需手动复制资源。已使用系统沙盒禁止读取旧缓存并禁止外部网络，验收冻结版 PDF/TXT、结果复用及重启取回。

同页普通段落扩大原生批次；跨页、跨栏长段沿用锁定引擎的对应方式。返回 JSON 会校验段落 ID、重复/遗漏、文字类型及占位符，失败段落局部重试；整批格式损坏或截断时二分缩小，过长单段按句界拆分。校验失败会中止交付，不把提示词或未验证结果填入 PDF。数字、纯链接、DOI、公式占位符和缩写允许原样保留。优化流程取消独立 Hello 连接调用，第一批真实内容同时验证连接。

“自动最低思考”根据模型列表能力与首批真实响应协商；仅明确的参数/取值不支持错误触发调整。供应商没有确认时显示“已请求最低，服务商未确认实际设置”。也可选择“服务商默认”。能力缓存按配置 ID、地址和模型隔离，完整结果缓存同时包含翻译协议版本和思考设置；旧污染段落缓存继续禁用。

配置历史支持命名、新建、切换、删除，同一地址可保存不同密钥。保存时地址或密钥变化会新增记录，模型/速度变化更新当前记录。切换后自动刷新模型，接口失败时保留选中的模型并可手填；有未保存修改时可保存、放弃或取消切换。翻译期间禁止切换。0.3 当前配置自动迁移，失败保留原记录；0.3 只保存过最后一套密钥，早先覆盖的配置需重新添加。

进度与历史记录请求数、在途数、限流重试、最近响应和请求耗时，并展示服务商实际返回的 token 用量；未返回的用量不作估算。“正在翻译”“上游限流，等待重试”“正在排版”区分当前阶段，进度百分比不是剩余时间估计。协议/限流测试与固定延迟基准：

```bash
.venv/bin/python -m unittest discover -s tests -p 'test_*.py'
.venv/bin/python scripts/benchmark_runtime.py
```

适配代码在项目自己的 `backend/translation_runtime.py` 和 `backend/request_runtime.py` 中，每个子进程启动时安装，并检查 BabelDOC 0.6.2 / PDFMathTranslate-next 2.9.0。无需修改虚拟环境或上游安装文件。没有跨任务断点续传、跨页拼批或自动切换供应商。

构建（Apple 芯片 Mac，已准备本项目依赖后）：

```bash
npm ci
.venv/bin/python -m pip install -r desktop/requirements-build.lock
.venv/bin/python -m pip install scikit-build==0.18.1 cmake==4.2.3 ninja==1.13.0 wheel==0.45.1
.venv/bin/python scripts/build_slim_opencv.py
.venv/bin/python -m pip install --force-reinstall --no-deps .runtime/slim-wheels/opencv_python_headless-*.whl
```

全新构建机应先用 Python 3.11 创建 `.venv`。构建脚本会运行后端回归、桌面 TypeScript 和 ESLint 检查，生成 App、ZIP、对应源码、第三方授权及 SHA-256。产物写入 `release/`，0.4.1 App 工作副本在 `build/package-0.4.1-macos-arm64/纸间.app`。

当前采用本地临时签名，未经过 Apple 公证。首次打开的操作与完整使用说明见 `desktop/使用说明.txt`。可用以下命令对冻结后的引擎做隔离验证；模拟供应商仅验证协议与处理链，不能据此推断真实模型译文质量：

## 网页开发入口的工作流

- 上传一份 PDF；源语言不在界面中设置。
- 翻译提示词要求模型逐段识别混合语言，再统一输出简体中文。
- 在页面填写任意 OpenAI-compatible API 的基础地址、模型名和密钥。
- 也可以在 `backend/api_config.txt` 中预设 base_url、api_key、model（每行一项 key=value），以及可选的 `model_reasoning_effort=none|minimal|low|medium|high|xhigh|max`；网页会自动读取，base_url 结尾不需要加 /v1。更安全的无落盘方式是设置 `PDF_TRANSLATION_API_BASE_URL`、`PDF_TRANSLATION_API_KEY`、`PDF_TRANSLATION_MODEL`、`PDF_TRANSLATION_MODEL_REASONING_EFFORT`（以及可选的 `PDF_TRANSLATION_QPS`），环境变量优先于文件。
- 配置文件路径可通过环境变量 `API_CONFIG_PATH` 自定义，例如 `API_CONFIG_PATH=~/my-keys.txt`。
- 81 页及以上的文档会自动按每部分 50 页（可调）交给 PDFMathTranslate-next 处理；其后端负责按页序合并。
- 浏览器通过 Server-Sent Events 显示解析、翻译、回填、合并的总体进度与当前分段。
- 默认使用 0.4 自动调度，批次目标为同页相邻段落约 1,536 原文 token、最多 16 段。兼容旧 `qps` 参数，新版请求字段优先；原生 JSON 数组保留每段 ID、公式与样式占位符，不做第二层批量代理。
- 默认交付纯译文版（原位替换文字）；在高级设置中按需生成左右对照版（左半页中文译文，右半页原文），避免每次任务都重复做第二次版式渲染。
- 翻译完成后会把原 PDF 的超链接、内部跳转、目录和元数据恢复到实际生成的输出版本中；恢复过程在统一的视觉坐标、PDF 原始坐标和目标插入坐标之间转换，覆盖旋转、缩放及非默认 CropBox，并且重复执行不会增加重复链接。
- 网页表单中的 API 密钥不会写入浏览器存储、日志或任务目录，只会随着当前任务留在本地服务内存中。若使用 `backend/api_config.txt`，该文件本身会保存密钥，服务会尽力将其权限收紧为当前用户可读写；共享机器上应改用环境变量或删除该文件。
- 0.4 优化流程的单次 HTTP 请求最多 120 秒；每个批次连同重试最多 5 次请求、累计 180 秒。429 自动降低并发与请求速率并遵守 Retry-After，502/503/超时采用带抖动退避；401/403 直接报告。取消会中断调度与退避等待。
- 默认跳过独立的自动术语提取阶段，直接进入正文翻译；该阶段会为几乎每个段落额外调用模型，论文任务通常不值得付出这部分等待时间。
- 当前安装的 BabelDOC 0.6.2 已弃用并忽略旧的表格文字 OCR 接口，因此界面不会发送这个无效开关；表格的几何结构与位置仍交给版式引擎保留，表格单元格文字翻译需等上游支持或另行实现。
- 为避免旧版本批量代理留下的错误译文被缓存复用，新任务默认跳过 PDFMathTranslate-next 的翻译缓存。确认缓存内容干净后，可设置 `PDF_TRANSLATION_USE_CACHE=1` 恢复缓存。
- BabelDOC 的模型、工作文件和缓存默认放在项目内 `backend/data/engine-cache/`，避免依赖用户目录权限；可用 `PDF_TRANSLATION_CACHE_DIR` 指定其他本地目录。
- 输出在交付前会扫描整份 PDF，进行 Unicode 控制分隔符归一化，并检查页数、文件完整性和多条高置信度 prompt 泄漏特征；校验失败会把任务标记为失败，不会提供“看似完成”的 PDF。
- 超链接与内部跳转按“尽力恢复”处理：少量链接未能保留时会显示警告，但正文 PDF 仍标记完成并允许下载；页数不一致、文件损坏或提示词泄漏等正文完整性问题仍会阻止交付。
- 当前本地回归已验证兼容配置到 OpenAI 客户端的转换和标准请求协议；首次接入某个供应商时，仍应先用 1-2 页代表性 PDF 检查该端点的实际响应、限流和译文质量。

## 架构

```text
浏览器界面 (React / Vinext)
        │ 上传 PDF + 本次 API 设置
        ▼
本地 Python 服务 (127.0.0.1:8789)
        │ 事件流（SSE）
        ▼
PDFMathTranslate-next / BabelDOC
        │ OpenAI-compatible requests
        ▼
你的 OpenAI 或兼容模型端点
```

网页开发入口的 PDF 及处理产物保存在本机的 `backend/data/jobs/`，在任务完成 24 小时后清理；桌面版数据在用户的 Application Support 中，历史与原稿持续保留，结果可自动保存到统一目录。只有为翻译所需的文本片段会发送到你配置的模型端点；原文 TXT 提取完全在本机进行。

为避免 API 密钥被误送到未知服务器，网页界面只接受 `localhost`、`127.0.0.1` 或 `::1` 作为译制服务地址；模型 API 地址仍可按需填写官方或兼容端点。若将来需要远程部署，应另行加入认证、TLS 与服务器端密钥管理，而不是直接放开这个限制。

如果首次运行需要下载 BabelDOC 的版式模型，服务会在第一次任务前完成下载。你的环境若设置了 `NO_PROXY`，不要写裸的 `::1`；本服务会自动移除这个会被 `httpx` 误解析为非法端口的条目。

## 重要边界

- PDFMathTranslate-next 的版式重建能力不是“像素级绝对保证”。扫描件、密码保护文件、复杂跨页表格、嵌入式图像文字与异形文字框仍应先以代表性页面试译。
- 上游引擎目前仍需要一个名义源语言设置；本服务在后台使用英文作为拉丁文字的排版基线，并以逐段自动识别提示词处理混合语言。德英混排的实际效果必须以试译结果判断。
- 本项目使用的 PDFMathTranslate-next 上游项目为 AGPL-3.0；如要把该工具对外提供为服务，请先自行评估相应许可证义务。

## 当前判断与优化计划

### 已处理的高优先级问题

1. **翻译污染与速度**：旧版 `BatchCollector` 把 BabelDOC 已经生成的 JSON 数组再次包装成编号文本，解析失败时还会把完整 prompt 当作译文返回。现已移除该代理，直接使用上游原生 JSON batching、重试和线程池。
2. **任务隔离**：旧版全局 collector 会在并行任务之间串混请求；现有实现每个任务直接建立自己的上游翻译进程，并限制同时运行的任务数（可用 `PDF_TRANSLATION_MAX_ACTIVE_JOBS` 调整）。
3. **超链接**：旧版使用 `saveIncr()` 且不检查重复；现已改为语义去重、旋转/缩放坐标映射、目录/元数据恢复和原子写入，并把恢复数量写入完成事件。

### 后续方向

1. 扩展更多供应商、扫描件与复杂版式的真实基准；0.4 的本次验收范围和速度记录见发布页附件，不将单个服务商的收益推及全部模型。
2. 增加用户可维护的术语表与专名策略（首次出现“中文（原文）”、后续统一），并用人工抽样评估一致性；仅靠提示词不能保证每个专名都正确。
3. 对扫描件中的图像文字、跨页表格和 RTL/竖排语言分别建立 fixture；当前引擎仍以“尽量保留”为目标，不能宣称任意语言和任意版式都像素级一致。
4. 补充后端接口测试、PDF 结构回归（页数/目录/链接/图像/字体）和渲染截图对比；生产使用前还应加入磁盘配额、密钥权限检查和失败任务清理。

验收底线：任何输出都不得包含翻译指令文本；链接数量与目标应与源文件一致，重复恢复不增加数量；页数、目录、图像对象和主要元数据应通过结构检查，失败段落不能静默退化为原始 prompt。

### 0.4.1 修复

部分 TeX 数学字体的原始括号在文本提取时表现为 NUL。现在核对同页源字形的嵌入字体、实际 glyph 和位置，仅放行可追溯到原稿的字形。升级启动时重新校验仅因旧 NUL 规则失败且仍有完整结果的任务，恢复 PDF / TXT，不重新请求 API。新出现或无法核对的 NUL，以及提示词污染，仍阻止交付。
