# 纸间 0.4.2 验收记录

日期：2026-10-23。以已发布 0.4.1 源码单独制作热修复，保留工作区 0.5 扫描功能开发。

## 问题及修复边界

23 页原稿在旧版中停在 85.46%，58 次 HTTP 请求全部成功，却因单个翻译单元耗尽共享额度而失败。旧实现把排队时间算入响应期限，并把拆分后已成功的子任务计入同一个五次请求上限。模型改写或丢失公式、样式标记时，重复原批次也无法恢复。

现在以没有取得进展的修复单元为计数边界：传输与内容重试有上限；有限的参数能力探测单独计数；排队不消耗响应期限。已经通过校验的段落保留，剩余段落与拆分后的子任务独立处理。返回格式错误、缺失或重复 ID、空响应、截断、占位符不全分别进入缩小批次、单段翻译和保留标记的文字分段修复。等价标记写法规范化后仍须完整性校验。无法修复时明确失败且不暴露下载。

默认生成中英对照 PDF，下载列表首先提供对照版；同时保留纯译文 PDF 和默认 TXT。缺少请求的对照 PDF 时禁止标记完成。界面区分接口响应与已校验段落，错误去掉多层 Original error 重复。

## 已完成验证

- 维护工作区 93 项 Python 回归通过；独立发布基线 70 项通过，其中运行时专项 24 项。TypeScript、ESLint、桌面前端构建通过。
- 同一份 23 页 PDF，DeepSeek 全文完成 128.85 秒；最终打包引擎上的 GLM 全文完成 203.33 秒。两者均校验 162 个段落，生成 23 页纯译文、23 页左右对照及两份 UTF-8 TXT。GLM 的一次上游错误已恢复。均关闭完整结果缓存。
- 本地打包引擎故障注入：畸形 JSON、逐次只返回部分段落、仅支持纯文本翻译、丢失公式/样式、长度截断、空选项响应、429 后 503 均恢复并下载 PDF/TXT；持续无效响应在有限重试后失败，下载被拒绝。公式案例使用原稿中三页，实际触发 16 个保留标记修复。
- 原有冻结进程、SSE、历史恢复、结果复用、取消及输出完整性检查通过。旧 BabelDOC 缓存和外部网络被禁止时，使用单独种子缓存仍可完成本地模拟翻译。
- 全部 23 页缩略图巡检，抽看公式、正文与参考文献页，并用 Poppler 查看对照首页。无残留 {vN}/style 标记；两个 PDF 各恢复 403/806 个链接；TXT 无非法控制字符。

## 推断与使用限制

这些检查证明所测文档、两个模型和所列故障路径能完成处理，不能保证任意服务商、任意 PDF 一定成功。保留标记的分段修复可能影响语序和衔接，界面和历史会记录提示；译文未逐句人工审校。发布内容不包含验证论文、译文、配置 ID 或 API 密钥；原稿和实际译文仅保留在本机。

GLM 样例另有 2 个纯译文链接、4 个对照版链接未能恢复，任务已保留提示；正文和文件生成正常。
