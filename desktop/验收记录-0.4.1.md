# 纸间 0.4.1：公式字体 NUL 误拦截修复

日期：2026-10-20。此补丁保留 0.4 的翻译、并发、思考策略和 API 配置逻辑，仅修复结果验证及已有结果恢复。

## 根因与修复

实测 15 页任务的原 PDF 第 5 页有两个 TeX `CMEX10` 公式括号，其文本层提取为 U+0000（NUL），但可正常显示。中文版保留相同的两个字形，对照版两个面板合计四个。原稿与输出的嵌入字体二进制一致，括号的字形和位置匹配，渲染对照一致。0.4 的“任何 NUL 都阻止交付”规则因此误报。

0.4.1 不删除 PDF 中这些字形，也不直接关闭检查。发现 NUL 后逐项核对同页原稿的嵌入字体 SHA256、实际绘制 glyph ID、字号及位置；同一字形在每个单页/对照面板只允许匹配一次。新出现、移位、换字体/字形、数量超出或无法证明来源的 NUL 继续阻止交付。提示词污染、页数、下载边界及完整结果哈希检查保留。

已验证并保留原字形时，任务会提示：PDF 可查看，但 TXT 无法完整表达原字体的公式符号，研究用途须对照原件。TXT 仍为 UTF-8，禁止控制字节不会写入导出文件。

## 已有任务恢复

升级启动时仅检查旧错误信息恰为 NUL 拦截、且磁盘仍有完整输出的失败任务。原稿、中文及所请求的对照版必须通过新规则和原有污染检查，才恢复交付；缺失或仍异常的任务保持失败。恢复前备份旧失败记录，重新补充链接及 TXT，保留原请求数、用量和时间，不重新调用 API。原文、配置和个人密钥保持本机保存。

## 验证结果

- 全部 **59 项 Python 回归测试**通过，含 7 项新增的真实 PDF 字体映射/恢复测试：源字形保留、双面板、原稿无 NUL、字体/字形/位置改变、额外字形、提示词污染和旧结果恢复/拒绝。
- 在这份 15 页任务的副本上恢复成功，73 次原请求统计保持不变，新增 API 请求为 **0**；中文与对照 PDF、原文与译文 TXT 四项齐备，TXT 无 NUL。
- 第 5 页公式渲染对照一致；渲染并检查全部 15 页接触表。结构和结果哈希检查通过。未据此宣称已全面校验论文语义、所有公式或所有字体。
- 补丁没有改变模型调用路径，未重新消耗额度跑速度对照；0.4 的速度记录另附，不能把此次恢复耗时当作新翻译速度。

Apple 芯片版本仍自带运行环境，首次资源准备与 0.4 相同；采用临时签名，尚未 Apple 公证。机器可读记录见 `validation-0.4.1.json`。发布内容不包含验证论文、译文、个人路径、配置 ID 或 API 密钥。
